Framework full-stack reativo e offline-first sobre Postgres padrão. Você escreve schema e funções em TypeScript; o Pulse cuida da reatividade, do cache local-first, da fila offline e dos conflitos, com uma engine em Rust na frente do banco.

Início rápido

Um comando monta o app já configurado: schema, contract, handlers, client com Vite e Postgres no Docker.

# 1. crie um app Pulse já configurado
npx @onveloz/pulse new my-app
cd my-app
pnpm install

# 2. suba o Postgres (wal_level=logical) e gere os tipos
pnpm db        # docker compose up -d
pnpm gen

# 3. rode a engine e o app
pnpm engine    # engine em http://127.0.0.1:8787
pnpm dev

Pré-requisitos: Node 22+, pnpm e Docker (para o Postgres local). A engine em Rust é baixada automaticamente pelo @onveloz/pulse-engine. Para usar um binário próprio, defina PULSE_SERVER_BIN.

Arquitetura

Uma escrita percorre nó → Postgres → reactor → SSE. A engine é dona dos pools, traduz a API de documentos para SQL e captura o conjunto de leitura e escrita de cada procedure. No commit, o change-set é comparado com a assinatura de leitura de cada subscription, e só reexecuta quem foi de fato afetado.

Para agregados (count/sum/min/max/avg) ela vai além: mantém o valor incrementalmente a partir do delta da mudança, sem reexecutar o worker nem tocar o Postgres. Só recorre à reexecução quando a manutenção exata não é possível.

Schema

Tabelas e validadores em TypeScript. Cada validador é tipo e checagem em runtime ao mesmo tempo.

import { defineSchema, defineTable, v } from "@onveloz/pulse-schema";

export default defineSchema({
  issues: defineTable({
    title: v.string(),
    description: v.collab(),  // campo CRDT (Yjs)
    status: v.union(v.literal("todo"), v.literal("done")),
  }).index("by_status", ["status"]),
});

Funções de servidor

Implemente o contrato com implement. O ctx.db é instrumentado: toda leitura entra no conjunto de leitura da função.

const os = implement(contract);

export const list = os.issues.list.handler(async ({ ctx }) =>
  ctx.db.query("issues").collect(),
);

export const setStatus = os.issues.setStatus.handler(async ({ ctx, input }) => {
  await ctx.db.patch(input.id, { status: input.status });
  return null;
});

São quatro tipos: reactive (query assinável), mutation (escrita transacional), analytical (consulta pesada, em pool isolado) e action (efeitos colaterais).

Client reativo

Crie o client a partir do typeof do contrato, sem codegen. O subscribe entrega o resultado inicial e, depois, cada atualização por SSE.

import { createClient } from "@onveloz/pulse-client";
import type { contract } from "../app/contract.js";

export const pulse = createClient<typeof contract>({
  url: "http://127.0.0.1:8787",
  headers: () => ({ authorization: "Bearer ..." }),
});

pulse.issues.list.subscribe(undefined, setIssues); // tempo real

Reatividade e agregados incrementais

Cada subscription guarda o conjunto de leitura da query: tabelas, colunas e filtros normalizados em DNF. No commit, o change-set é confrontado com essas assinaturas, e reexecuta só quem foi afetado, linha a linha. Filtros (eq/in/like/is null/…), orderBy multi-coluna, paginação e joins compostos no handler entram nesse casamento.

Agregados escalares são mantidos sem reexecução: um count() filtrado sobe e desce pelo delta; sum/min/max/avg se ajustam pela linha que entrou ou saiu. Quando a manutenção exata não dá conta (conjunto vazio, ou a linha que segura o extremo saiu), o Pulse recorre à reexecução, sempre correto. O GET /metrics expõe ivmApplied (manutenções) e ivmPushed (entregas) para você acompanhar o acerto.

Modo offline

Escritas via pulse.$local.mutate são otimistas e duráveis: a UI atualiza na hora, a mutation entra numa fila persistida no IndexedDB e o cache de leitura fica salvo. A app continua funcionando mesmo se você recarregar a página com o servidor fora do ar. Ao reconectar, a fila drena sozinha, com escrita exactly-once. 

await pulse.$local.mutate(
  ["issues", "setStatus"],
  { id, status: "done" },
  { optimistic: (store) => { /* atualiza o cache na hora */ } },
);

pulse.$onSyncStatus((s) => setLive(s === "connected"));
const pendentes = await pulse.$local.queue.size();

Você nunca resolve conflito na mão: o servidor reexecuta a mutation e o client faz rebase do overlay otimista.

Colaboração (CRDT)

Campos v.collab() são documentos Yjs. Duas pessoas no mesmo campo (ou você offline em duas abas) têm as edições mescladas, nunca sobrescritas. A mescla roda no servidor (Rust/yrs), dentro da transação da mutation. 

import { CollabHandle } from "@onveloz/pulse-client";

const handle = new CollabHandle(opts, {
  id, getDocPath: ["issues", "getDescription"],
  applyUpdatePath: ["issues", "applyDescription"],
}, subscribe);

Migrações

No estilo Prisma/Drizzle: você gera arquivos SQL versionados e editáveis a partir do diff do schema contra o último snapshot, sem precisar de banco para gerar. 

pulse migrate dev [nome]   # gera migrations/NNNN_nome.sql do diff e aplica no dev
pulse migrate deploy       # aplica as pendentes em ordem, cada uma em uma transação
pulse migrate status       # lista cada uma: applied / pending / drift
pulse db push              # sync direto schema → banco, sem arquivos

Cada arquivo aplicado fica registrado no journal _pulse_migrations com o hash do conteúdo. Editar uma migration já aplicada é recusado: ela é imutável, então crie uma nova. Drops destrutivos saem comentados por padrão; remoção e redefinição de índice são geradas automaticamente.

CLI

pulse new <app>         # scaffold completo: schema, contract, client, Docker
pulse gen [schema.ts]   # gera os tipos Doc/Id
pulse dev [app.ts]      # roda a engine + worker em dev
pulse start [app.ts]    # produção: sobe a engine (depois de migrate deploy)
pulse deploy [app.ts]   # bundle de release
